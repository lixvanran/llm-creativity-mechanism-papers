## 三条必须一起讲的限定

> **这三条不是某一篇的内部问题，而是跨篇共享、且会改变读者对结论强度判断的事实。**
> **主动说，比被逐条追问强得多。**

**1 · 型号池静默下架，历史 dual 臂读数的分母是 4，不是 5**
`MODELS` 池第 5 位 `MiniMax-M2.1` 已 404，5 分支臂的第 5 支返空，被 `if o` 过滤，**5 支静默变 4 支，表上看不出来**。晚间独立复核还查出 `MiniMax-M2`（第 6 支）同为死型号，**任何声称用满 6 支的场合，读数都要先核支数是否真为 6**。历史对照值 `+0.0483` 因此**作废**（它算在 4 支口径下），对照域必须**重跑**。

**2 · 层1 的归因天花板：注意力机制归因不成立，不是「没做」**
全仓**没有任何**注意力权重 / logits / hidden state / 内部激活数据；托管 API **静默忽略 `logprobs`**，NLL / perplexity / typicality / PMI 全族作废；无 GPU。唯一允许的写法：**「与注意力机制相容，但本文未检验该假设」**。这是**能力边界，不是未尝试**。

**3 · 「不可分辨」≠「无效应」**
凡报「不可分辨」，**必须同时报检出力地板**；门槛锚在**本批自己的噪声地板**，不许拿文献阈值当判决线；方向一致只能作辅助条件且须先过 H0 标定。
 H0 的唯一合法来源 = **同臂、同题、不同 rep**（rep 差异是纯噪声，天然零分布）。
**θ₀ 以题内 rep σ 为单位**（如 θ₀ = 1.33 σ），引用时必须写成「≥ θ₀ 个题内 rep σ」——否则会被误读成绝对阈值。

## 复现与核验

```bash
# 1) 从 Markdown 重建全部 DOCX（★ 构建命令固化 ⇒ 外部可逐字节重建）
cd tools && bash build_docx.sh ../papers

# 2) 核验 DOCX 无单元格丢失
python3 tools/check_docx.py papers

# 3) 完整性校验（每个文件一行 sha256）
sha256sum -c SHA256SUMS.txt
```

**为什么把 pandoc 参数写死随包交付**：pandoc 默认 `smart` 扩展会把 `"` → `“”`、`...` → `…`，同一份 md 在不同机器/不同 pandoc 版本下可能产出不同的 docx，外部就复核不了我们交付的 docx，关闭 `smart`，**md 与 docx 逐字一致**，「单元格零丢失」才是个真判据。
