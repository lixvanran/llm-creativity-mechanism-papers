## 摘要

主流大语言模型按下一个词的概率续写，产出因此倾向于"流畅但无主"。要让 Agent 的写作像人一样**由情感或观点推动**，自然的做法是给它一个持久状态：先形成立场，再由状态组织每一步的取舍。但**如何测量"改变"是观点驱动的，而不是被 prompt 措辞或采样噪声带出来的，一直缺少一个干净的实验协议**——而且这个测量本身极容易出错。

本文把"驱动"拆成**两条通路**，给出各自的读数与地板，并在**三轮架构（v1–v4）**上报告结果。

**① 反馈通路**（观测 → 状态 → 产出）成立且强分离：效应量是纯重跑方差的 **9.13×**。

**② 驱动力通路**在几何读数上归零，而换用判官读数后结论**方向相反**。在 G01 单题上，15 个臂对全部落在 0.053–0.077 的窄带内，而纯重跑地板是 0.0720 ⇒ 地板高于信号；换用**对着目标直接问的判官两两比较**后，同一批产出给出**方向相反**的分离。⇒ 我们据此主张：在创作任务上，**"状态是否驱动了产出"不能用产出之间的相似度来回答**——相似度测的是"内容在哪里"，而驱动是关于"内容里有什么"。

**③ ★ 判据的循环性。** 当状态经由**代码强制**（必含/禁含实体）生效时，"状态变了 ⇒ 产出变了"是**恒真命题**，不能充当驱动力证据。我们给出唯一不循环的读数设计（决策只以自然语言进入生成流程，此时产出的变化才是模型的选择），并把它写成一条可迁移的检查题：**"这个读数能不能是恒真的？"** ★ 本文的一次正式实验正是在**开跑 5 分钟后主动终止**——因为候选提示告知了打分依据 ⇒ 读数接近恒真 ⇒ 实验作废重跑。

**④ ★ 状态进选择层（v4）：失败位置很精确。** 状态塑造候选**有效**（候选符合状态率 blind 0.0741 → 给缺口 0.6667，**9 倍**）；**状态化打分选择无效**（干净臂 **9/9 完全打平**，gap 均值 0.0，align 均为 0.3148，n=9 ≥ 6 ⇒ **可判定地不成立**，不是"不可判定"）。⇒ 由此定位出一个**结构性两难**：状态**不进**候选 ⇒ 产出无状态指纹 ⇒ 打分无处发力；状态**进**候选 ⇒ 打分**接近恒真** ⇒ 该臂差值不能作证据。**"状态化选择"要么无效、要么恒真。**

**⑤ ★ 双判官交叉验证。** 同源判官与被测共享偏好，因此我们把同源判官与两个跨厂商判官（grok）在 G01 上对照：**三个判官在核心对比上给出完全相同的数字（0胜6负，位置一致率 1.00）**，方向在六个对比中全部一致 ⇒ **该方向不是某个判官家族的偏好**。

我们同时量化了判官读数的**三种失效模式**（天花板效应、位置偏差、严格度差异），并把**位置去偏 + 一致率硬闸**作为 LLM-as-judge 成对比较的标准前置条件：实测中多对对比的胜负为"3胜3负"（看似无差异），而其**位置一致率为 0.00**——真相是判官在随机作答。

**关键词**：LLM 代理 · 状态驱动生成 · 创造力测量 · 判据效度 · 位置偏差 · 预注册 · 边界结论

## 1 引言

### 1.1 问题

主流 LLM 按下一个词的概率续写，产出因此倾向于"流畅但无主"：它能写得很像样，但换一个作者、换一个立场，产出的骨架几乎不变。要让 Agent 的写作像人一样**由情感或观点推动**，自然的做法是给它一个持久状态：先形成立场，再由状态组织每一步的取舍——**写什么、怎么排序、什么被略过**。

### 1.2 为什么这不容易

难点不在"造一个状态机"，而在**证明产出真的被它组织了**。这里有一整类几乎必然踩到的陷阱：

| 陷阱 | 表现 | 后果 |
|---|---|---|
| **读数恒真** | 状态经由代码强制生效 ⇒ "状态变了 ⇒ 产出变了"是代码的必然结果 | 读数无法区分"状态驱动"与"代码驱动" |
| **状态退化为 prompt** | 状态被拼进 system prompt | 测的是提示词工程，不是状态驱动 |
| **几何读数无分辨力** | 产出之间的相似度差异落在噪声地板内 | **把"测不出来"读成"没有差异"** |
| **判官随机作答** | 位置偏差未去偏 | **把随机读成"无差异"** |
| **口径漂移** | 判据一改，读数就改 | 跨版本比较全错 |

⇒ ★ **本文的核心不是提出一个更好的架构，而是把这五个陷阱逐一变成可执行的检查。**

### 1.3 我们的做法

1. **拆成两条通路**：反馈（状态 → 产出）与驱动力（状态的**内容** → 取舍 → 产出），各给读数与地板。
2. **给出一条不循环的读数设计**，并把"这个读数能不能是恒真的？"写成通用检查题。
3. **在三代架构上执行**（v1–v3 状态机；v4 状态进选择层），每轮都报告**失败位置**，而不只是成败。
4. **量化判官的三种失效模式**，并给出硬闸。
5. **收口到一个定位**：若"驱动"最终必须进入训练与采样，本文贡献就是**一个定位 + 一套可廉价复用的检验工具**。

### 1.4 贡献

| # | 贡献 | 性质 |
|:-:|---|---|
| 1 | 反馈通路成立且强分离（**9.13×**） | ✅ 实证 |
| 2 | **不循环读数**的设计与必要性 + 通用检查题 | ✅ 方法 |
| 3 | ★ **读数错配如何制造一个看起来干净的负结果**，以及如何被三判官交叉对照识破 | ✅ 方法（本文最有价值的部分） |
| 4 | 判官三失效模式的量化与硬闸 | ✅ 方法 |
| 5 | ★ **状态化选择的结构性两难**（要么无效、要么恒真）与失败位置定位 | ✅ 负结果 + 定位 |
| 6 | 一个**廉价的前置检查**：投入训练侧改造前，先测出推理时架构的上限 | ✅ 实践建议 |

### 1.5 本文的诚实边界（先说不能主张什么）

> ⚠️ 本文**不**主张：① 状态机已经能驱动 Agent；② 状态机优于等强度提示词注入；③ D1–D3 是"思想驱动"的直接测量（它们是**代理指标**）；④ 几何相似度能回答"驱动"问题（本文正是要排除它）。

## 2 相关工作

### 2.1 生成机制一侧：NTP 与"先想再写"

- 📄 **Nagarajan, Wu, Ding & Raghunathan (2025)**, *Roll the dice & look before you leap: Going beyond the creative limits of next-token prediction*, arXiv:2504.15266, **ICML 2025 (oral)**：NTP 学不到"先想一个抽象点子再围绕它生成"；解法是换训练目标（teacherless / diffusion，让模型一次性预测整段输出，从而被迫在 prompt 编码阶段就形成 plan）并把**随机性从输出端挪到输入端**（seed-conditioning：一次决定走哪条 plan，采样本身完全确定）。
- 📄 **Olatunji & Sheppard (2025)**, *Next Token Prediction Is a Dead End for Creativity*, arXiv:2505.19277 —— ⚠️ **perspective 论文，非实验** ⇒ 不得当作"已有实验支持"引用。

⇒ 这是本文的**外部锚点**：从**训练侧**得到的结论方向，与我们从**推理时架构**一侧得到的方向一致（见 §7.4）。

### 2.2 测量一侧：创造性写作的交互式基准

见 §7.5 的构念效度讨论与附录 B。本文的位置是**方法学**：我们不提出新的创造力基准，我们提出**如何不把"测不出来"读成"没有差异"**。

### 2.3 "驱动"一侧：状态、立场与角色

- 📄 **Typicality bias**（arXiv:2510.01171，6,874 对）：人类**系统性偏好更典型的那个** ⇒ 优化"个性"时，perplexity / logprob / 离语料中心的 embedding 距离是**反向指标**，真实关系是**倒 U**。
- 📄 **Alvarez-Gonzalez et al.**（arXiv:2109.01900）：模型预测"读者感知到什么"比人类读者还准 ⇒ **任何纯文本指标在原理上只能测"读起来像"，测不到驱动力本身**。
- 📄 **Diversity Collapse**（ACL 2026 Findings 13）：专家权威 persona 压多样性（Vendi 最低 4.65 vs 最高 8.08，质量只差 0.62）⇒ **权威必须从判官身上剥掉**。

⇒ ★ 这三条共同支撑本文的一个立场：**要测"驱动"，必须用过程侧或结构侧的读数，纯文本相似度不行。**

## 3 问题设定

### 3.1 ★ 主张的边界（先说不能主张什么）

我们研究的是 **③由情感/思想驱动的生成过程**——**不是**①文本里有感情词，**不是**②文本里有主张。

> **要让内容层的视角过滤（选哪些细节/怎么排序/什么被略过）来自模型自己承担的内在状态，而不是外部指令或概率最高解。**

不拆开 ①②③ 就会退化成「情感提示词工程」——那条路在论文簇的 A 篇与层2 侧已被实测封死（18 个工作流变体 13 个更差；融合门矛盾率是直调的 10.5 倍）。

### 3.2 两条通路

```
                    ┌──────────────────────────┐
   观测 / 立场 ───▶ │  状态（agent 进程内）      │
                    └───────┬──────────┬───────┘
                            │          │
              ┌─────────────▼──┐   ┌───▼──────────────────┐
              │  反馈通路       │   │  驱动力通路            │
              │  状态 → 产出    │   │  状态的"取舍内容" → 产出 │
              └────────────────┘   └───────────────────────┘
                    ✅ 成立               ❌ v3 几何归零
                    （9.13×）             ⚠️ v4 定位到"选择器"
```

| 通路 | 含义 | 读数 | 判决 |
|---|---|---|:-:|
| **反馈通路** | 观测 → 状态 → 产出 | 换初稿扰动状态历史 | ✅ **成立且强分离** |
| **驱动力通路** | 内在状态 → 取舍内容 | 换决策 / 换缺口 | ❌ **v3 几何读数归零**；⚠️ **v4 定位到选择器** |

⚠️ **我们刻意分开两条通路**，因为早期把反馈通路读成"驱动内容有效"是**归因错误**：`probe_arch.py` 的置换变体复用**同一个 `state0`**（`keeps` 不变），只换初稿 ⇒ 变的是"**历史**"，不是"**取舍内容**"。

### 3.3 研究问题

| # | 问题 | 对应读数 |
|:-:|---|---|
| **RQ1** | 状态能否改变产出的内容构成？ | 反馈通路（换初稿 / 换状态） |
| **RQ2** | 状态**的取舍内容**能否改变产出？ | 驱动力通路（换决策 / 换缺口） |
| **RQ3** | 如果测不出，是**真没差异**，还是**读数不分辨**？ | 地板 + 跨读数轴 + 跨判官交叉 |
| **RQ4** | 状态能否进入**选择层**并被有效读取？ | v4（状态 → 候选 → 打分 → 选 1） |

## 4 方法

### 4.1 架构化状态机（v1 → v4）

| 版本 | 状态怎么进生成 | 与"层2 提示词"的同构性 | 主读数 |
|---|---|:-:|---|
| **v1** | 状态 → prompt 文本 → 一次生成 | 高 | 几何（实词 2/3-gram Jaccard） |
| **v2** | 状态 →（代码强制：必含/禁含实体） | 中 | 零判官离散结构量 |
| **v3** | 状态 →（**只以自然语言**进生成，无代码强制） | 低 | 几何 + 判官 |
| **v4** | 状态 → **K=3 个完整候选** → 打分 → 选 1 | 低 | ★ **全部零判官** |

★ **v4 的关键设计约束**（写在代码注释与自检里）：
1. **候选必须是完整可交付文本**。若候选只是提纲、后面再写一次正文，状态就又退回 prompt 层。
2. **打分不能直接按 priority 选**。那会恒真。⇒ 打分对象是**从候选正文抽取的实际行为**。
3. **两个打分器评估同一批候选**（`WF-v4` 与 `WF-v4-blind` 内部都这样做）⇒ 差值**只来自打分器**，不是两次独立采样。

### 4.2 臂

| 臂 | 候选提示 | 调用数 | 作用 |
|---|---|---|---|
| `A` | —（单次直答，无 system） | 1 | 基线 |
| `WF-v4` | 立场 + keeps + **缺口内容与实体** | 4 | 状态 → 候选（可测），**打分恒真风险高** |
| `WF-v4-blind` | 立场 + keeps + **只给缺口数量** | 4 | ★ **H3 的判决所在** + 盲从地板 |

### 4.3 探针

| 变体 | 含义 | 作用 |
|---|---|---|
| **D0** | 纯重跑（同输入同决策，**初稿也重写**） | **地板** |
| **D2** | 换初稿（状态历史变，取舍内容不变） | 反馈通路 |
| **D2'** | 换决策（gaps / 观测 / 实体全同，只翻 depth/priority） | 驱动力通路 |
| **D3** | 换无关议题的缺口 | 驱动力通路（对照） |

### 4.4 ★ 不循环读数（本文的核心方法论贡献）

**问题**：当状态经由**代码强制**生效时，"状态变了 ⇒ 产出变了"是**恒真命题**。

**我们给出唯一不循环的读数设计**：

> **决策只以自然语言进入生成流程**（不写必含/禁含实体），此时产出的变化才是**模型的选择**。
> ⇒ 通用检查题：**"这个读数能不能是恒真的？"** 答案若是"能" ⇒ 停。

★ **本文的一次正式实验正是靠这条纪律拦下来的**：

> v4 第一版候选提示**告知候选"缺口涉及的具体词"** ⇒ 候选"照做就能命中" ⇒ 状态化打分的 align 接近恒真 ⇒ **H3 失去意义**。
> 该实验在启动约 **5 分钟后被主动终止**（不是跑完再看）；已落盘的 **7 条不进入任何结论**，被新一轮整批覆盖。
> ⇒ 修订后加 **`WF-v4-blind` 臂**：状态照常构建（观测 + 决策），但**候选提示里不含任何缺口内容/实体**，只给"有 N 个还没想清楚的地方，具体是什么由你自己判断"。
> ⇒ 该臂里，状态化打分**唯一的信息来源是事后从正文抽行为** ⇒ **彻底非恒真**。
> （自检 **25/25**，含一条防回归：`blind` 提示里不得出现任何状态实体/缺口文字。）

### 4.5 判官读数

**绝对打分**（题内每臂 3 次）与**两两比较**（位置去偏 + 一致率硬闸）并行；绝对分**只在题内相对排序**使用，**不跨判官比**（见 §7.2 严格度差异）。

### 4.6 预注册与纪律

- 四个待判命题**在看到读数之前**写死，并留「口径变更记录」栏。
- 分析单元 = **题**；题内取中位数。
- 失败路径**显式列出**，不静默剔除。
- **"无效应"与"无检出力"必须分开**：落在噪声包络内写「**不可分辨**」。

## 6 结果

### 6.1 ✅ 反馈通路：成立且强分离（v1 批次）

以"换初稿"扰动状态历史，产出相对基线的实词 Jaccard：

| 读数 | 均值 |
|---|---|
| **D2 换初稿** | **0.0176** |
| **D0 纯重跑地板**（同初稿重跑） | **0.1606** |
| **分离比** | **9.13×** |

⇒ 状态历史确实主导了产出的内容构成，效应远超同输入重跑的方差。

⚠️ **但这条读数测的是反馈通路，不是驱动力通路**（§3.2 的归因纠正）。

### 6.2 ❌ 驱动力通路：几何读数上归零（v3 批次，NL 通道）

| 变体 | 逐例 J | 均值 |
|---|---|---|
| **D0** 纯重跑 | 0.0972 / 0.0574 / 0.0613 | **0.0720** |
| **D2'** 换决策（gaps/观测/实体全同，只翻 depth/priority） | 0.148 / 0.0973 / 0.0777 | **0.1077** |

#### 6.7.8 为什么选择器读不出状态：一个可操作的诊断

状态化打分建立在"**事后猜**候选有没有写到那些实体"上。而模型**没有把状态以可抽取的形式留在产出里**：
- 取舍声明率只有 22% / 11%（`A` 臂 0%）；
- 候选即使声明了取舍，**回避的对象也常常不是状态指定的那些实体**（`R_takeoff-orig` 恒 0 就是这个现象的直接证据）。

⇒ ⇒ **要让状态化打分有意义，候选必须在可观测层面显式表达状态**（例如"我这一轮只写 A，B 就不展开了"），使打分建立在**结构化绑定**上，而不是事后猜实体命中。
⚠️ 这与 v3 已确立的结论一致：**绑定必须结构化**。

## 7 讨论

### 7.1 两条读数轴：可核验性 × 分辨力

我们在 v2 得到的经验是"**干净 ≠ 有力**"。v3 的结果迫使我们把这个说法改得更精确：

> **不是"干净"与"有力"互斥，而是"可核验性"与"分辨力"由不同读数承担，同一个读数不能同时承担两者。**

- **代码强制通道**（必含/禁含）：可核验性满分——必含命中 9/9，禁含随观测换源 8/8，代码封闭率 70%、驱动相关槽位 4/4 封闭。**但它对驱动力零分辨力**，因为"状态变了 ⇒ 产出变了"是代码的必然结果。
- **几何读数**（实词 2/3-gram Jaccard）：零判官、可复现、成本低。**但它在本任务的臂间区分度为 0**：全部 15 个臂对落在 0.053–0.077 的窄带，而纯重跑地板是 0.0720 ⇒ 地板高于信号。
- **内容性判官读数**（两两比较）：有分辨力（6 票一致 0–6），但引入判官失效风险（饱和、位置偏差、严格度差异）⇒ 必须配自检与硬闸。

⇒ **实践含义**：研究"状态是否驱动了产出"时，**几何相似度应当被排除为主读数**——不是因为它"不严谨"，而是因为在产出长度与体裁相近的创作任务上，它测的是"内容在哪里"而非"内容里有什么"。

### 7.2 判官读数的三个失效模式（可复用的流程建议）

我们在实现中踩到并量化了三种失效，每一种都会**系统性地**把"有差异"读成"无差异"：

| 失效 | 现象 | 处置 |
|---|---|---|
| **天花板效应** | 判官 4.20 在 D1 上把 18 篇全打 3.000 ⇒ 绝对分零分辨力 | 改用两两比较；或换更严的判官 |
| **位置偏差** | 多对对比胜负"3 胜 3 负"（像无差异），但**位置一致率 0.00** ⇒ 判官在随机作答 | **交换位置各跑一次**，一致率作硬闸 |
| **严格度差异** | 4.20 偏松（方差 0.49）、4.3 偏严（1.86）⇒ 绝对分不可跨判官比 | 只用**题内相对排序** |

⇒ 我们主张这套流程（**自检 → 位置去偏 → 一致率硬闸 → 题内配对 → 相对排序**）应成为"LLM 状态是否驱动产出"这类研究的**标准前置条件**。

### 7.3 失败的结构性根因：取舍对象取自初稿已有内容

即使把读数做对，v3 的**几何读数**仍给出零信号。追查设计后，我们定位到一个结构性原因：

> 代码规定"缺口相关实体 ⊆ 初稿"（逐字校验）⇒ **要写的内容本来就在稿子里**。

于是"写它 / 不写它"**不是取舍**，只是"保留还是删掉已有内容"；而模型做**改写**时天然倾向保留原有内容 ⇒ **取舍信号被改写惯性淹没**。

⇒ **对下一版设计的硬要求**：取舍的对象必须取自**初稿里没有的东西**（新的证据类型、新的立场维度、新的类比），或让取舍作用于**结构位置**（写哪一段、占多少篇幅、论证顺序），而不是"某个词出不出现"。
⚠️ 这条与 §7.1 的结论是独立的：即使读数完美，当前 v3 的取舍设计也表达不了取舍。

### 7.4 对相邻结论的独立验证与指引

我们的结果从**推理时架构**一侧指出：仅把"立场 / 取舍"写进 prompt（哪怕配上封闭枚举、代码强制、结构化中间态），**不足以**让产出被观点驱动。这与 📄 **Nagarajan et al.（ICML 2025 oral）** 从**训练侧**得到的结论方向一致：要让模型先想再写，必须改**训练目标**（teacherless / diffusion）并把**随机性从输出端挪到输入端**（seed-conditioning）。

⇒ 我们的结果因此不是"状态机无用"的终局判断，而是一个**定位**：它把"驱动"的责任从推理时架构，指回了训练与采样。
⇒ 同时它给出一个**廉价的前置检查**：在投入训练侧改造之前，先用**判官两两比较**测一轮推理时架构的上限——若连"有状态 vs 等预算自我说明"都测不出分离，那么训练侧改造就是必需的，而不是可选的。

### 7.5 ★ 与层1 的接口（不同源，但方向一致）

| | 层1（现象与分层） | 本文（层4） |
|---|---|---|
| 问什么 | 为什么**想法变少** | 产出是否**由状态组织** |
| 测什么层 | 搜索空间层（解码 / 表征 / 架构） | 内容层（状态 → 取舍 → 产出） |
| 证据可互换？ | **否** | **否** |

⚠️ **两篇不同源，读者不应把 (i) 的证据当成 (ii) 的。**
★ **但方向一致**：层1 实测**架构层干预无效**（工作流臂与直调臂的 α 配对 5/5 不可分辨），本文实测**推理时状态机不足以制造驱动力**。⇒ 两者都把"驱动"的责任推回**更深的层**（训练 / 采样 / 内部机制）。

### 7.6 同源判官：能用，但只能当交叉验证的一端

额度耗尽迫使我们用 MiniMax 自己的端点当判官，而被测生成器正是 MiniMax-M3。这在原则上**违反**本文的判据纪律（同源判据无效）。我们的处理是把它降级为**交叉验证的一端**，并加上一条可复用的经验：

> **同源判官在"相对比较"上的可用性，取决于能否用跨厂商判官做锚点。**
> 若同源判官与跨厂商判官在同一批数据上**方向一致**（本文：三个判官在核心对比上给出完全相同的数字），则该方向**不是**单一判官家族的偏好；
> 若无法做这个锚点（跨厂商不可得），则同源判官的结果**只能**作为**待验证的观察**报告，**不得**进入主结论。

⇒ 推论出一条对资源受限研究者的实用建议：**优先把跨厂商额度花在"锚点对比"上**（少量题、少量对比、双判官），而不是把它平摊到全部实验上。本文的额度分配恰好做反了（先把额度花在 G01 的全维度上，多题反而只能靠同源判官），这是流程上的一个教训。

⚠️ 同时提醒：**同源判官与同源生成器共享的不只是"偏好"，还有风格**。若被测臂之间的产出风格差异本身就是判据的一部分，同源判官可能因此偏好某一臂 ⇒ 方向一致**不足以**排除偏差。这正是 §8 把人类盲评列为必做项的原因。

## 8 局限与威胁有效性

**统计效力**：分析单元是**题**。本文主读数来自 **3 题**（G01 / T07 / T10；T06 因生成端超时退出）× 3 次重复 × 2 位置。n = 3 题属小样本，**只作方向性判断，不报显著性**（v4 的 Fisher p = 0.47 / 1.0）。
⚠️ T10 上 D1 的 A vs WF-a3 是 3胜3负（唯一例外）⇒ **方向并非在每题每维都一致**。

**★ 最大的效度缺口：多题判官是同源的。** 跨厂商判官（grok）因 OpenRouter key 额度耗尽（`403 Key limit exceeded (total limit)`）只覆盖 G01；多题由同源判官 `MiniMax-M3` 承担。
⇒ 同源判官与被测生成器共享偏好，**不能被当作独立证据**。
⇒ 缓解措施只有一条：G01 上的**双判官交叉验证**（§6.4）显示三个判官方向一致 ⇒ 但这**不能替代**多题上的跨厂商判官。**这是本文最需要补做的一项。**

**单模型**：被测只有 MiniMax-M3。`temperature=0` 在该模型上仍非确定性 ⇒ 一切结论依赖题内重复与题内配对，不依赖逐字重放。

**零判官与判官的双重约束**：几何读数无判官但分辨力随题而变（G01 无分辨力、T10 有）；判官读数有分辨力但可能失效。本文用三条地板 + 位置去偏 + 一致率硬闸来约束，但仍不能排除"判官与我们的偏好同源"（我们与判官都是语言模型，可能共享同一种"什么算有观点"的直觉）⇒ **本工作不能替代人类盲评**。

**题面与题材**：三道题均为中文、单一作者视角、给定体裁（观点文 / 科普小品 / 求职自述）；结论不外推到英文、多轮对话或高度专业题材。

**构念效度**：D1–D3 是**代理指标**，不是"思想驱动"的直接测量。D3 试图逼近"概率检索 vs 人写"的区别，但由语言模型判定，可能与 📄 **Sui et al. 2026** 报告的**不确定性差距**高度相关也可能无关；我们**未**做该计算（该文需要模型似然，而当前 API 不返回 `logprobs`、OpenRouter 亦返回 `logprobs=None`、沙箱无自托管能力）⇒ 列为后续工作。

**v4 的读数脆弱性**：`align` 依赖"实体"抽取，而实体词表来自 gap 抽取，存在措辞敏感性；§6.7.4 的恒 0 读数已暴露这类脆弱性。

**对本文结论的自我限制**：本文**不**主张"状态机已经能驱动 Agent"。我们主张的是三件更小但更牢的事：(i) 一条不循环读数及其必要性；(ii) 判官三种失效模式的量化与硬闸；(iii) 一次读数错配如何制造出一个看起来干净的负结果。
⚠️ §6.3 的方向一致分离虽然跨 3 题、跨 3 判官，但**没有人类盲评**、**没有构念效度检验**、**多题判官同源** ⇒ 它足以支持"几何读数不能回答这个问题"这一**方法论**结论，**不足以**支持"状态机有效"这一**实质**结论。

**流程性缺陷（已修正，列出以备复核）**：判官任务曾与产出生成**并发**，导致读到不完整数据；判官失败曾被静默计入"解析失败"而掩盖了 HTTP 429 限流；语言闸门曾用"整体中文占比 ≥0.9"误杀含术语的中文长文。三者均已修正。

## 9 结论

我们从"让 Agent 的输出由观点/情感推动，而不是仅由下一个词的概率决定"这一问题出发，做了三件事。

**第一，把"驱动"拆成两条通路，并给出各自的读数与地板。** 反馈通路（观测 → 状态 → 产出）成立且强分离（**9.13×**）；驱动力通路（取舍内容 → 产出）需要一条**不循环**的读数才能测。

**第二，指出了一个被忽视的方法论陷阱并给出修正。** 当状态经由**代码强制**生效时，"状态变了 ⇒ 产出变了"是**恒真命题**，不能充当驱动力证据；我们给出唯一不循环的读数设计（决策只以自然语言），并把它写成一条可迁移的检查题：**"这个读数能不能是恒真的？"** 我们进一步量化了判官读数的三种失效模式（天花板效应、位置偏差、严格度差异），并把**位置去偏 + 一致率硬闸**作为 LLM-as-judge 成对比较的标准前置条件。
★ 这条纪律**真的拦下了一次事故**：v4 第一版因候选提示告知打分依据而接近恒真，实验在开跑 5 分钟后被主动终止并整批作废重跑。

**第三，发现我们自己的负结果是读数错配的产物，并把它变成了可复用的工具。** 在几何读数上，全部臂对落在 0.053–0.077 的窄带内，纯重跑地板（0.0720）高于信号；而在**对着目标直接问的判官两两比较**上，同一批产出给出**方向相反**的分离。我们甚至记录了一个**同一批产出、两种读数、相反解释**的直接例子（T10：几何 J 最小的一对恰是判官判定"状态机更像由观点驱动"的一对）。

⇒ 这些结果共同支持一个更一般的结论：**在创作任务上，"状态是否驱动了产出"这个问题，不能用产出之间的相似度来回答。** 相似度测的是"内容在哪里"，而驱动是关于"内容里有什么"。

⇒ ★ **而 v4 把这个定位又推了一步**：状态塑造候选**有效**（9 倍），但状态化打分**无效**（9/9 打平）⇒ 瓶颈在**选择器读不出状态**；而要让打分有意义，状态必须以**结构化绑定**留在产出里 ⇒ 于是问题被收敛成："**状态必须在生成过程内部起作用**"。
⇒ ⇒ **"状态化选择"要么无效、要么恒真** —— 这是当前形态的边界。

⚠️ **本文不主张**状态机已经能"驱动"Agent——跨厂商判官的多题复现、人类盲评与构念效度检验都还欠着。

⇒ 我们也提出一个**廉价的前置检查**：在投入训练侧改造之前，先用判官两两比较测出推理时架构的上限——若连"有状态 vs 等预算自我说明"都测不出分离，训练侧改造就是必需的而非可选的。
