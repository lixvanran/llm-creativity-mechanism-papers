## 0. 机制（★ 按用户思路，★ 不加自创机制 ★）

> **让单一 Agent 反复集中注意力于每一个 token** ＝
> · **只有 1 个 agent**（★ 不是多路、★ 不是并行 ★）
> · 输入被**机械切分**成 token 序列（★ 切分规则事前写死、★ 不得用 gold ★）
> · **每一个 token 都被单独聚焦过**（★ 不许跳过 ★），★ 且是**反复**（多轮回到 token）★
> · 最后用这些逐 token 的检查结果**汇总作答**

★ **"token" 的机械代理定义（★ 必须写清、★ 闭源 API 拿不到模型内部 token ★）**：
★ API 无 tokenizer ⇒ ★ 本批的 token ＝ **字符/词级切分**：★ 连续的 ASCII 字母数字与 `%.%/-` 合成一个 token、★ 其余每个字符各自成 token ★（★ 例如 `7450MB/s` → `7450` `MB` `/` `s` ★）。
★ ⇒ **这是"逐 token"的机械代理，不是模型内部 token** ⇒ ★ **措辞边界**：★ **不许写"改变了模型的注意力"** ★ ⇒ ★ 只写「**改变了单次作答中被显式逐个重访的输入片段集合**」 ★。

## 1. 五臂（★ 全部是【单 agent】、★ 与上一批的多路拆散正交 ★）

| 臂 | 做法 | 阶段数 | 分离什么 |
|:-:|---|:-:|---|
| **B0 `direct`** | 单次直答（★ 层3 `arm_direct` **逐字** ★） | 1 | 基准 |
| **T1 `token_tag`** | 逐 token 角色标注 → 汇总作答 | 2 | "逐 token 标注" 单独的效果 |
| **T2 `token_probe`**（★ 主臂 ★） | 逐 token 角色标注 → **逐 token 追问** → 汇总作答 | 3 | ★ **完整版「反复聚焦」** ★ |
| **T3 `token_shuffle`** | ★ 与 T2 **完全同流程**，★ 只把**清单里的 token 顺序打乱** ★（★ 原题面照给 ★） | 3 | ★★ **归因闸门** ★★：★ 打乱后若照样有用 ⇒ "清单"只是**多写了一遍题面**；★ 若失效 ⇒ 起作用的是**逐个看清（语义）** ★ |
| **T4 `sentence_tag`** | ★ 把切分单元从 **token 换成句子**（★ 其余同 T1 ★） | 2 | ★ **粒度对照** ★：token 粒度是否比句子粒度更好 ★ |

★★ **T4 是粒度对照**：★ 若 T1 ≈ T4 ⇒ ★ token 粒度本身没带来额外东西 ★。

## 8. 已知缺陷（★ 事前写清 ★）

1. ★ **字符级 ≠ 模型内部 token** ⇒ ★ 只能写"逐个重访输入片段"，★ **不能写"改变了模型的注意力"** ★。
2. ★ **T1/T2/T4 共用阶段1 产物** ⇒ ★ 这三臂在阶段1 上不独立（★ 但阶段1 的输入完全相同、★ 属共用而非混杂 ★）。
3. ★ **R1 可跨批比的条件**：★ 判官模型（M2.5）＋ 传输层（FastJudgeLLM）＋ 尺子（measure.py）三者与上一批一致；★ 但上一批 B0 的判官只覆盖部分单元 ⇒ ★ 跨批参照只作量级参照、★ 不作判决依据 ★。
4. ★ **T3（打乱）会破坏清单的可读性** ⇒ ★ 若模型在 T3 上直接"看不懂清单"而放弃细读 ⇒ ★ 那 T3 与 T2 的差异**混着"可读性"因素** ⇒ ★ 只能判为「**失效**」、★ 不能反推「**逐个看清**是唯一机制」 ★。
5. ★ **单 agent ⇒ 无路间冗余读数**（★ 上一批的 R2 不适用 ★）；★ 本批的机制读数是 **R7 token 覆盖率 ＋ T3/T2 对照** ★。
