## 0. 为什么必须接（不是"锦上添花"，是**读数合法性**问题）

| | 生成侧 | 选择侧 | 读出的量 |
|---|---|---|---|
| **ToT（原文）** | b 个分支 | **强**：value / vote + 选择器 | **选择后的收益**（CoT best-of-100 **49%** → ToT b=5 **74%**） |
| **我这三轮（`n3`/`n8`）** | n 个分支 | **无** | **选择前的面宽**（模态数 / 有效秩） |

⇒ ⇒ ★ **两者的读数不是同一个量，不能互相引用。**
⇒ ⇒ ★ **但如果不接 ToT 原版臂，我就永远只能写"加支数有效"这种无法定位的话** ——
因为「有效」是相对**什么**有效？相对**没有选择器**？那 ToT 的 74% 跟我的是两码事。

⇒ ⇒⇒ **接 ToT 的真实目的不是蹭基线，是让"选择器强度 × 发散量"这个问题第一次可测。**

## 1. ToT 源码核验（`FINDINGS.md` §1，本组已下载核验过）

```python
# solve() 的三段：
new_ys    = [get_samples(task, x, y, ...)]              # ← 独立 gpt() 调用
values    = get_values(task, x, new_ys, ...)             # ← 独立 gpt() 调用
select_ids = sorted(ids, key=lambda x: values[x])[:n]   # ← 纯 Python
```

`method_select == 'sample'`（ToT 自带的随机化选择）：

```python
ps = np.array(values) / sum(values)
select_ids = np.random.choice(ids, size=args.n_select_sample, p=ps).tolist()
```

**四个可插拔槽位**：

| 参数 | 可选值 | 我们要接的取值 |
|---|---|---|
| `method_generate` | `sample` / `propose` | `sample`（★ 必须是 `sample`：只有 `sample` 才产生多分支） |
| `method_evaluate` | `vote` / `value` | ★ **两个都接**（`value` = 逐分支打分；`vote` = 多数投票） |
| `method_select` | `sample`（按价值加权随机） / `greedy` | ★ **两个都接**（⇒ 正好构成「选择器强度」的两个极端） |
| 搜索 | BFS / DFS | ★ **BFS 一层**（多步搜索需要可回溯状态与 part-level 评价器，**本项目的开放写作题不满足** ⇒ 见 §5） |

★ **已核实的两件事（别再犯）**：
- ToT 的生成与评估是**两个独立调用**，不是同一个 model call（曾有一篇 preprint 转述错误，已在 `FINDINGS.md` §2 更正）
- ToT 的**状态外置**：`y` 是累积的 Python 字符串，**搜索不发生在模型的上下文窗口里** ⇒ ⇒ 我们接 ToT 时**也应保持状态外置**，不要塞进 context

## 2. ★★ 臂定义（**5 个臂，正好把"选择器强度 × 发散量"交叉出来**）

> **命名纪律**：臂名必须能看出改了什么。`n8` 这种名字看不出「有没有选择器」⇒ 这就是昨晚表述失败的原因之一。

| 臂名 | 生成侧 | 评估侧 | 选择侧 | **它在问什么** |
|---|---|---|---|---|
| **`tot_greedy_b5`** | b=5, `sample` | `value` | `greedy` | ★ **ToT 原版**（最强基线） |
| **`tot_vote_b5`** | b=5, `sample` | `vote` | `greedy` | ToT 的 vote 评估器版 |
| **`tot_sample_b5`** | b=5, `sample` | `value` | `sample`（加权随机） | ★ ToT 的随机化选择器（**"选择器弱"那一极**） |
| **`tot_greedy_b1`** | **b=1** | `value` | `greedy` | ★ **ToT 退化对照**（= 单链 CoT + 评估）⇒ 隔离「b>1」这一个变量 |
| **`nosel_b5`**（= 昨晚的 `n8` 同族） | b=5, `sample` | **无** | **无** | ★ **我们自己的读数**（只测面宽） |

⇒ ⇒ **交叉设计**：
- `tot_greedy_b5` vs `tot_greedy_b1` ⇒ **b>1 的净效应**（ToT 原文 49% vs 74% 的那 25pp，在这里复现）
- `tot_greedy_b5` vs `nosel_b5` ⇒ **选择器吃掉了多少面宽**（★ 这才是层2 的核心问题）
- `tot_greedy_b5` vs `tot_sample_b5` ⇒ **选择器强度**
- ⇒ ⇒ **四组对照在**同一批题、同一预算**下跑 ⇒ 一次拿到 4 个可分离的效应

## 3. ★ IO 契约（**照抄 ToT 的调用边界，不自创**）

| ToT 侧 | 我们的侧 | 约束 |
|---|---|---|
| `get_samples(task, x, y, n_generate_sample, prompt_sample, stop)` | `LLM.chat(prompt, n=..., stop=...)` | ★ 必须是 **n 次独立调用**（不是一次调用 n 个候选）—— 因为 ToT 的"多分支"就是多次独立采样 |
| `get_values(task, x, ys, n_evaluate_sample, cache_value=True)` | `LLM.chat(VALUE_Q, branch)` **每个分支一次** | ★ 评估**必须独立于生成**（否则就是同源污染）；`cache_value` 可省但**必须记缓存命中** |
| `select_ids = sorted(ids, key=values)[:n]` | `gates/base.py::Select(mode='greedy')` | ★ 已有等价物（`FINDINGS.md` 已确认）⇒ **直接用，不重写** |
| `np.random.choice(ids, p=values/sum(values))` | `Select(mode='sample')` + `_weighted_sample` | ★ 我在第四组已修过 `Select.sample`（原实现恒等于 greedy）⇒ **可直接用** |
| `y` 外置累积 | 分支文本不塞回 context | 保持状态外置 |

⇒ ★ **预算对齐**：ToT 的 b 个分支 = b 次生成调用 + b 次评估调用。
⇒ ⇒ **对照臂必须按调用数对齐**（不是按 token 对齐）⇒ **否则又是一次"不同预算下的比较"**（我在 `BESTOFK-EQUIV.md` 里已写过 $ 轴，此处用**调用数**轴，理由写进报告）

## 4. ★ 因变量（**主读数必须定义上就能检出效应** ← 这是昨晚的教训）

| 量 | 定义 | 合法性检查 |
|---|---|---|
| **主读数**：**选择后收益** | 选中分支的质量分（`VALUE_Q` 打分均值 / 数值一致率） | ★ 跨臂可比（都是"选出来的那一条"） |
| **副读数**：**选择前面宽** | 候选集合的模态数（**绝对值**，不是 `秩/n`） | ★ **绝不用含 n 作分母的量**（昨晚的假结论根因） |
| **副读数**：**选择器消耗率** | (选择前面宽 − 选择后面宽) / 选择前面宽 | ★ **这是层2 的新因变量**：选择器强度对"面"的消耗 |
| **副读数**：有效秩（连续量） | PCA 谱参与比 | ★ 只能**题内**比；**不跨 n 比较** |
| **副读数**：数值一致率 | `num_consistency.py`（零判官） | 只对有唯一数值答案的理科题有效 |

⇒ ⇒ ★★ **新增因变量「选择器消耗率」是这一批的真正产出** ——
它把"融合门是双输"（第三轮）与"加支数有效"（昨晚）**接成同一个方程**：
**总面宽 = 发散量 × (1 − 选择器消耗率)** ⇒ ⇒ **层2 的设计问题因此变成可测量的两因子问题。**

## 5. ⚠️ 这批**不做什么**（照抄 ToT 的前提，不能假装它成立）

ToT 原文的任务设定（Game of 24）满足三条前提，**本项目的开放写作题一条都不满足**：

| ToT 前提 | 开放写作是否满足 | 后果 |
|---|---|---|
| 问题**可分解**为中间步骤 | ❌ | 不能做多步 BFS/DFS ⇒ **只接一层 BFS** |
| 有**可回溯的状态** | ❌ | 不能做 DFS 回溯 |
| 有 **part-level 评价器** | ❌（我们只有整体 `VALUE_Q`） | ⇒ ★ **这正是"塌缩"要发生的地方** ⇒ ⇒⇒ **我们的题不是 ToT 的题，这是我们的研究对象，不是缺陷** |

⇒ ⇒ ★★ **诚实定位**：
**我们不是"复现 ToT"，我们是"测 ToT 的前提在非分解任务上不成立时会发生什么"** ——
⇒ ⇒ ★★ 而这**恰好**就是层1（注意力闭合）与层2（设计）之间的桥：
**ToT 靠 part-level 评价器把"中途的思维面"显式化；我们没有它，所以要靠架构把面撑开**
⇒ ⇒ ★ **⇒ 这就是"层2 是主战场"的真正理由**，比之前任何说法都硬。
