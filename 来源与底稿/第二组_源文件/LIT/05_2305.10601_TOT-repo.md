## 1. 核心机制（实现层）

| 项 | 内容 |
|---|---|
| **输入** | `args`（命令行）+ 一个 `Task` 对象。三个 task：`Game24Task`、`TextTask`、`CrosswordsTask`。**有状态**：搜索状态 = 一串部分解文本 `ys`（beam）。 |
| **状态表示** | **纯文本列表**。`ys = ['', ...]` 起手，每步变成 `ys = [y + z for z in proposals]`。**没有类、没有 dataclass、没有树对象** —— 树是隐式的（`infos` 里存了每步的 `ys/new_ys/values/select_new_ys`）。 |
| **动作/算子** | 全部下沉到 `Task` 的四个静态方法（`bfs.py` 只调用它们）：<br>• `standard_prompt_wrap(x,y)` / `cot_prompt_wrap(x,y)` —— 采样式 prompt（naive run）<br>• `propose_prompt_wrap(x,y)` —— **提议式**：Game24 把"还剩哪些数"塞进 prompt 一次要 8 个候选；Crosswords 把已有 thought 翻译成字母约束<br>• `value_prompt_wrap(x,y)` —— **价值评估**：Game24 分两段（中间步用 `value_prompt` 评"剩余数字能否到 24"，最后一步用 `value_last_step_prompt` 判"这个答案对不对"）<br>• `vote_prompt_wrap(x,ys)` —— **集合投票**（Creative Writing 用）<br>• `test_output(idx,y)` —— **任务 oracle**，Game24 用 sympy 验算，Text 用 GPT-4 打 1–10 分 |
| **过程/回路** | `bfs.py:solve()`：`for step in range(task.steps)` → 生成 → 评估 → 选择 → 继续。<br>**停止条件**：**固定步数 `task.steps`**（Game24 = 4，Text = 2）。★ **没有早停、没有阈值、没有"找不到就停"**（论文自己在改进建议里提了 "BFS could early stop when solution is found"）。<br>★ `stops` 列表按步给不同的停止串（Game24 每步 `'\n'`，Text 第 1 步 `'\nPassage:\n'`、第 2 步 `None`）。 |
| **输出** | `ys`（最后一层的 b 个候选）+ `infos`（每步的完整轨迹）+ `usage_so_far`（token/美元累计）。 |
| **谁来评价** | **两套并存**：<br>• **搜索内部**：`get_value` / `get_votes` → **同一个 LM 自己评估**（`gpt(value_prompt, n=n_evaluate_sample)`）⇒ **自评污染在此**<br>• **任务结果**：Game24 = sympy oracle（干净）；**Text = GPT-4 judge，代码里硬编码 `model='gpt-4'`**（`text.py: gpt(prompt, n=5, model='gpt-4')`）⇒ **即使 `--backend gpt-3.5`，判官仍然是 gpt-4**；当 backend 也是 gpt-4 时就是**纯自评**。 |

**★ 成功率指标的精确定义（★ 关键，论文没写清）**

## 3. ★ 它的「成功标准」是什么（实现层）

- **任务 oracle**：Game24 = sympy 精确验算（`test_output`）；Crosswords = 环境的 `r_letter` / `r_word`；**Text = GPT-4 judge 1–10 分**（`n=5` 取平均）。
- **搜索内部启发式**：**同源 LM 自评**。`get_value` 用 `task.value_prompt_wrap` 让 LM 输出 `sure/likely/impossible`，`game24.value_outputs_unwrap` 把它映射成数：
  ```python
  value_map = {'impossible': 0.001, 'likely': 1, 'sure': 20}  # TODO: ad hoc
  ```
  ★ **代码注释自己写着 `# TODO: ad hoc`** —— 价值尺度是手工拍的。
- **★ 一个不显眼但很重要的实现细节（★ 我们的判据可以直接抄）**：`game24.value_outputs_unwrap` 的第一行
  ```python
  if len(y.strip().split('\n')) == 4 and 'answer' not in y.lower():
      return 0
  ```
  ⇒ **格式不合规的候选直接判 0**（不是给低分，是排除）。这正是"**结构不合规就不算数**"的判据 —— **和我们的坑 ③（判据载体必须是结构不能是措辞）完全同构**。我们可以直接借用这个"结构先行"的形式化。
- **★ `get_value` 的缓存**：`if cache_value and value_prompt in task.value_cache: return task.value_cache[value_prompt]` ⇒ **同一个评估 prompt 只调一次 LLM**。这是**成本优化**，但也意味着**评估不是独立的**（同一 prompt 的多次采样被当成一次）⇒ **统计上要注意**。
- **★ `get_values` 里的怪癖**：
  ```python
  if y in local_value_cache:  # avoid duplicate candidates
      value = 0
  ```
  ⇒ **重复的候选直接给 0 分**（注释说是"避免重复候选"，但效果是**惩罚重复**）。这是一个**隐式的多样性惩罚**，虽然实现粗糙。⇒ **对"新颖性/冗余度"的判据有参考价值，但绝不能用措辞相似度实现**（我们的坑 ③）。
- **否证条件**：Crosswords 的 `−prune` / `−backtrack` 消融（在 notebook 里）；Game24 的 best-of-k 换算对照。**都没有代码化，只有日志。**
- **★ 有没有报"不可分辨"？** —— **没有，但官方自己做了最诚实的一次动作**：
  - README 明确写出复现值 69% vs 论文 74%，并说 "**We hope to aggregate multiple runs in the future to account for sampling randomness and update the paper**"。
  - 论文的 judge 分数标准差（0.56）被明确报出，让读者能自己判断 6.93 vs 7.56 是否显著。
  - **但**：这两个任务（24点、填字）**都没有 CI**，只有单点；而 24 点 n=100 ⇒ 二项 95% CI 约 **±9pp**（我算的 69% 的 CI 是 **59.9–78.1**）⇒ **论文的 74% 和复现的 69% 在统计上完全不可区分**，而 74 vs 49 的 25pp 差距也只有约 2.5σ。

## 5. ★ 对我们项目的可迁移点

**最值钱的一条：★ 这份代码给了我们两个可以直接抄的"结构性判据"，都绕开了措辞相似度（我们的坑 ③）。**

1. **"格式不合规 ⇒ 判 0"（结构先行）**
   ```python
   if len(y.strip().split('\n')) == 4 and 'answer' not in y.lower():
       return 0
   ```
   ⇒ **不比较措辞，只检查结构槽位是否齐全**。我们"依据包核验"的第一层可以照这个形式做：**一个维度的证据必须落在指定的结构字段里，字段缺失 ⇒ 该维度不承重（而不是"给个低分"）**。
2. **"重复候选 ⇒ 赋 0"（离散化的冗余惩罚）**
   ⇒ 不算 embedding 余弦，只做**离散去重**。这正是我们坑 ②（embo-01 embedding 无分辨率）的解药：**用离散结构相等/不等代替几何相似度**。⇒ 我们的"维度冗余"判据可以做成"**该维度是否引入了一个之前不存在的结构槽位**"，而不是"文本有多不一样"。
3. **★ `logs/` 的做法（实验即档案）**：文件名把**全部超参**编进去（`gpt-4_0.7_propose1_value3_greedy5_start900_end1000.json`），每个 entry 存 `steps`（每步的 ys/new_ys/values/select_new_ys）+ `usage_so_far`（token/美元）。
   ⇒ **我们的 DEV 实验档案应该照这个格式存**：每条实验记录 = {全部超参, 每步的中间状态与评估值, token/美元账}。**只要存了这个，我们随时能自己重算噪声地板 δ。**
4. **★ `usage_so_far` 的成本账**：`models.py` 全局累加 completion/prompt token 并按硬编码价目表折算美元，**每条日志都带**。⇒ 我们必须做同样的事（我们的坑 ④ 涉及"带宽 > 信号"，**带宽的直接货币成本必须逐条记账**）。
5. **路线 A（固定拓扑）**：`Task` 的四个静态方法（`standard/cot/propose/value/vote prompt_wrap` + `test_output`）就是一套**"拓扑 = 槽位 + 算子"的最小接口**。⇒ 我们可以照它定义我们的"思维面"接口：**每个维度 = 一个 prompt_wrap 槽位 + 一个可核验的产出槽位**。
6. **路线 C（人定拓扑 + 训练调参数）**：`method_generate`（sample/propose）× `method_evaluate`（value/vote）× `method_select`（greedy/sample）×（b, T）**就是一张现成的拓扑参数表**。我们只要把"参数"从这些离散选项扩到我们的维度集，就得到了 C 路线的一个可运行骨架。

**必须改什么才能用**
- **必须加早停 / 停止条件**（现在只有固定步数）。
- **必须加重复评估与 δ**（官方自己都承认 74→69 是随机性）。
- **必须改 judge**：`text.py` 里 `model='gpt-4'` 硬编码，判官与被测同源。**我们必须把 judge 的模型参数化，并与被测解耦。**
- **value map 必须重做**（`# TODO: ad hoc`）。
- `get_value` 的缓存会让重复评估失去独立性 —— 我们做重复测量时**必须关掉缓存**。

## 6. ★ 不可迁移 / 会误导我们的点

1. **★ 最会骗我们的：README 里那句"this shouldn't affect the main conclusions of the paper"。** 74% → 69% 是 **-5pp**，而 24 点的 n=100 ⇒ 二项 95% CI 约 **±9pp**。我重算的 69% 的 CI 是 **59.9–78.1**，**论文的 74% 就在这个区间里**。⇒ **"74% vs 49%" 这个 headline 的 25pp 差距本身也只有约 2.5σ。** 再叠加我重算的 crosswords 日志（prune 69.0/44.0 vs 论文 78/60）—— **官方放出来的轨迹系统性地低于论文读数**。⇒ **这棵树在三个任务上都存在"论文数字 > 可复现数字"的系统性缺口。**
2. **★ "success rate" = ANY(5 个候选里任一命中)**，不是"平均"。⇒ **b=5 给了 5 次机会**，而 "CoT best of 100" 给了 100 次机会。**论文用 Figure 3(a) 把两者换算到"访问节点数"轴上来比较，但 Table 2 的数字本身不同口径。** ⇒ 我们引用 "74%" 时必须说清是 ANY 口径。
3. **★ 判官同源**：Creative Writing 的 1–10 分由 **gpt-4 自评**（`model='gpt-4'` 硬编码），而生成者也是 gpt-4。⇒ **我们的坑 ⑥ 原样成立。** 而且 judge 的**单次分数 sd ≈ 0.54**，而 ToT 与 CoT 的差是 **0.63**（1–10 制）⇒ **差距只有约 1.2 倍判官噪声**。人工盲评 41:21:38 ⇒ **59% 分不出来。**
4. **★ value 尺度是 ad-hoc 的**（`{'impossible':0.001,'likely':1,'sure':20}`，代码里自带 TODO）⇒ 我们不能抄这个尺度，也不能抄"用 sure/likely/impossible 三分类"这个粒度 —— **它太粗，且无法核验。**
5. **★ 它完全不用 embedding** ⇒ **没有踩 embo-01 坑**。但我们若为了"多样性"加一层 embedding 余弦，**就会踩坑 ②**（中文句级几何无分辨率 ⇒ 27 条断言压成 1 条）。⇒ **坚持用离散的"结构槽位是否重复"判据。**
6. **量纲完全不同**：ToT 的"宽度 b"是**并行候选分支数**，不是**信息维度数**。**"b=5 比 b=1 高 29pp"绝不能读成"多 4 个思维维度 = +29pp"。** 这是本次 6 篇里最容易被我们误引的数字。
7. **措辞相似度在改写型环节失效（我们的坑 ③）**：ToT 在 Creative Writing 上给了直接证据 —— **IO+refine 7.67 > ToT 7.56**，即**"改写型"环节比"搜索型"环节更有效**。⇒ 我们若在改写型环节主张"思维面带来增益"，要格外小心。
8. **代码成熟度低**：`run.py` 默认参数与论文不符、gpt-4o 价格写反、`--reflect_max` 式死参数、任务包有重复逻辑。⇒ **抄协议，不抄代码。**

## 8. 读完后我自己的一句判断

**最值得抄的**：**"结构不合规就判 0" + "重复候选就判 0" 这两条离散判据**。它们把我们从"算一个相似度然后卡阈值"（embo-01 的死路）里救出来 —— **判据可以是纯布尔的**：证据是否落在指定槽位？该槽位是否与已有维度重复？**这两问都不需要 embedding，也不需要措辞相似度**，而它们的失效方式是可解释的（"这维没承重"、"这维和第 3 维重复"）。这恰好是我们坑 ②③ 的正解。

**最容易骗我们的**：**"74%"这个数字**。官方 README 自己说复现只到 69%；我重算 crosswords 的官方日志也发现 prune 版只有 69.0/44.0（论文说 78/60）。⇒ **ToT 的三个任务上，"论文数字 > 可复现数字"是一个系统性缺口**。更糟的是"success rate = ANY(b=5)"这个口径 —— **5 次机会对 100 次机会**。**我们若把"b=5 提升 29pp"当成"多 4 个维度能提升 29pp"，我们会把分支数误当成维度数，这是我们这个项目最危险的误读。**

**最该复现的一个数字**：**"换一次随机种子，74% → 69%"**（作者自认），以及我重算出的 **n=100 时 69% 的 95% CI = 59.9–78.1**。⇒ **ToT 在它的招牌任务上，headline 效应的效应量/噪声比只有 ~2.5σ。** 我们必须把**自己每个候选配置的重复评估次数**提到能把这个比值拉到 3σ 以上的水平，否则我们做的所有"净维度增益"结论都会站在同样薄的地基上。**这个数字（2.5σ）就是我们项目里"维度增益至少要有多少才可信"的现成参照。**
