## 0. 每道题的产物（**一个题一个目录里的 4 个文件**）

```
/workspace/lab/routes/DEV/
  evidence/D01.json          # 依据包
  gold/D01_cards.json        # 金标卡组（由 conclusion_space 机械派生，见 §4）
  devset.json                # 汇总（由合并脚本写，你们不要写）
  MANIFEST.json              # 汇总（由合并脚本写，你们不要写）
```

### `evidence/Dxx.json` 结构
```json
{
  "task_id": "D01",
  "title": "一句话题名",
  "domain": "技术/常识判断",
  "ask": "题面（自造，20–60 字，含明确可判定的要素）",
  "conclusion_space": [
    {"id": "C1", "text": "候选结论/行动/判定（3–8 条）"},
    {"id": "C2", "text": "..."}
  ],
  "key_conclusions": ["C2", "C4"],
  "evidence": [
    {"id": "EV-01", "text": "一条原子事实（20–90 字，只含事实，不含建议/结论）",
     "source": {"url": "https://...", "quote": "可逐字引用的原文某一句", "date": "2026-01-15"}}
  ],
  "evidence_second_source": [
    {"id": "EV-01", "status": "confirmed", "url": "https://...", "note": "第二来源如何印证"}
  ],
  "notes": "构建说明：哪些条目是推断类、为什么"
}
```

## 1. 题面（`ask`）要求
- **自造**，20–60 字，**含明确的可判定要素**（数字/阈值/条件/主体关系）。
- 答案**不是开放式的"给我建议"**，而是**可以判定对错的**（这才能有金标与否证条件）。
- 覆盖下列题型之一：常识判断 / 短期规划 / 分类判定 / 冲突权衡 / 数量比较 / 规则应用。
- 领域尽量分散（见 §5 分配表）。

## 2. 结论空间（`conclusion_space`）要求
- **3–8 条**，每条是一个**可被判定"成立/不成立"的命题**。
- ⚠️ 它必须**覆盖该题的全部正确结论空间**，但**不能多到无法区分**
  （若任意答案都能命中全部 C ⇒ 这道题没有判别力）。
- `key_conclusions` = **必命中**的子集（通常 1–3 条）⇒ 用于 R2（关键结论不丢失）。

## 3. 依据包（`evidence`）纪律（**沿用已验证的教训，逐条照做**）
1. **只收原子事实**，不收建议、不收结论（"因此应该选 X" 这种**不是**事实）。
2. 每条**必须能逐字引到某个来源的某一句** ⇒ `source.quote` 填**原文那句话**（可截断到 120 字）。
3. **"需要推断才能得到的"条目单独标类**，不混进主依据 ⇒ 放 `notes` 里说明，并在
   `evidence_second_source` 里以 `status: "inferred_only"` 单列。
4. `evidence_second_source`：**每条主依据都要填第二来源核验结果**
   （`confirmed` / `single_source` / `inferred_only`）⇒
   ⚠️ 理由：矛盾率同时含"模型说错"与"oracle 说错"，后者无法从指标里分离。
5. **依据包只进核验/裁决侧，不进被测臂的提示词**（本约束由执行侧代码保证，构建者不必处理）。
6. **构建过程不读任何已有答案。**

## 4. 金标卡组（`gold/Dxx_cards.json`）要求
- **由 `conclusion_space` + `key_conclusions` + 依据包机械派生**（可复现 ⇒ 不依赖抽取器 ⇒ 抽取器自检有效）。
- 结构：
```json
{
  "task_id": "D01",
  "n_cards": 12,
  "cards": [
    {"card_id": "G01",
     "claim": "一句自足的事实性陈述（含主体与具体数值/条件）",
     "supports_conclusions": ["C2"],
     "evidence_ref": "EV-03",
     "evidence_class": "事实",
     "is_load_bearing": true,
     "decision_changed": "它支撑 C2：没有它，结论 C2 不成立"}
  ],
  "distractors": [
    {"card_id": "G90", "claim": "看似合理但依据包不支持的陈述（用于测假阳性）",
     "why_wrong": "依据包第 X 条说……，与此相反/未提及"}
  ]
}
```
- **正样本卡 ≥ 12 张/题**；每张卡必须能指到 `evidence` 里的一条（`evidence_ref`）**且**指向某个
  `conclusion_space` 条目（`supports_conclusions` 非空）。
- **`is_load_bearing` 规则**：`supports_conclusions` 非空 **且** 该结论在 `key_conclusions` 里 **或**
  该卡能改变某个结论的成立性 ⇒ `true`；否则 `false`（供抽取器自检区分"真但闲"）。
- **干扰项 ≥ 3 条/题**（`distractors`）⇒ 用于测假阳性；**干扰项必须看起来合理但依据不支持**
  （例如把阈值说反、把适用条件扩大到别的情形、复述题面）。
- ⚠️ 金标的构造**不得**依赖任何抽取器/判官输出（否则自检失效）。

## 6. 质量闸门（每个构建者**必须自检并在交付里贴出输出**）
1. **JSON 可解析**（`python3 -c "import json;json.load(open(...))"`）。
2. **每条依据的 `source.quote` 与 `source.url` 非空**，且 `url` 以 `http` 开头。
3. **`conclusion_space` 3–8 条**；`key_conclusions` ⊆ `conclusion_space` 的 id。
4. **金标正样本 ≥ 12 张**、**干扰项 ≥ 3 条**；每张正样本卡有非空 `evidence_ref` 与 `supports_conclusions`。
5. **金标卡的 `evidence_ref` 都能在 `evidence` 里找到**（脚本核对）。
6. **题面不含禁用三题的任何关键词**（"自行车/公路赛/骑行/高考/620/报志愿/朗诵/诗歌"等）。
7. **泄漏自检**：把 U1–U4 的题面关键词（"湖北""620""AI/人工智能专业选校""自行车""1.6km""气质量表/多血质""作业""假"）
   对全部 DEV 文件做 grep ⇒ **0 命中**。

## 6.5 ⚠️ 工具故障通报（2026-10-21 02:20 实测）

> **本沙箱的 `web_fetch` 全面失败**（`file load failed` / `caller aborted`）⇒ **不要在它上面重试**。
> **✅ 改用 `web_search`**：它会把**抓到的页面正文整段放在结果的 `content` 字段里**。
> 做法：把你要引用的那句的关键成分放进 query（精确查询词），`count` 取 3–5，
> 从 `content` 里**逐字抄**正文段落填进 `source.quote`；换一组词再搜一次即得第二来源。
> ⚠️ 拿不到逐字原文的条目 ⇒ **不要凭记忆写**；要么换一条能引到的事实，
> 要么标 `status: "single_source"` 并在 `notes` 写明"未取得逐字原文"。
