# 1. ★ 卡住的例子：`pl_20261105` 卡死在一次网络调用

## 1.1 症状（**可回源，不补造**）

| 观测项 | 读数 | 怎么测的 |
|---|---|---|
| 进程状态 | **`S`（sleeping）**，`Threads: 3` | `ps -o pid,stat,etimes,args -p 942` |
| 打开的 socket | **1 个** | `ls -l /proc/942/fd \| grep -c socket` |
| CPU 时间 | 618 + 17 clock ticks（**不增长**）| `awk '{print $14,$15}' /proc/942/stat` |

⇒ ⇒ ★ **判定**：★ **不是沙箱问题、不是 OOM、不是代码异常** ⇒ ⇒ **是卡在一次进行中的网络调用上**（S 状态 + 1 socket + CPU 不增长 + 零写入）⇒ ⇒ **⇒ 客户端没有请求级超时 ⇒ ⇒ 这是本条的根因。**

## 1.2 处置（★ 三个动作，逐条可核）

| # | 动作 | 命令 | 结果 |
|:-:|---|---|---|
| 1 | **定向 kill**（★ 不用 `pkill -f`）| `kill -9 942` | ★ 命中唯一目标 PID ⇒ **不匹配自身 shell**（★ `pkill -f "train_policy_w"` 会匹配到承载它的 bash ⇒ 今天已栽过一次）|
| 2 | **移出合并** | `mv runs/pl_20261105 runs/_partial_pl_20261105` | ⇒ `merge_policies.py runs/pl_*` 的 glob **不再命中它** ⇒ ⇒ **残 seed 不进平均，但【原件保留】** |

⇒ ⇒ ★★ **★ 这是「失败路径不许静默归零」的正面执行**：★ **失败的那次没有变成"少一个样本"混进平均，而是被【显式移出 + 原件保留 + seed 数如实报】。**

# 2. ★ 反复错误的例子：旧奖励版本（24 样本）**学不出偏好**

## 2.1 已尝试方法

* 6 seed 并行 REINFORCE（`launch_train.sh`），每 seed **6 轮 × 3 样本 = 18 个训练样本**
* 动作空间 57 参（`u`6 修复型 + `v`2 范围 + `t`3 强度 + `m`6×6 失败×修复 + `arb`3 + `nf`4 发散度 + `mm`3 合并方式）
* **基线** = 跨轮移动平均（`base`）；学习率 `lr`（`train_policy_w.py::reinforce`）

## 2.2 ★ 关键假设（当时的奖励设计）

```
r = −λ_conflict_pairs(0.8) × 跨槽位矛盾对数
    −λ_cost(0.02) × 调用数
    （★ 当时【没有】 λ_trap·陷阱命中，【也没有】 λ_width·分支分散度）
```

## 2.3 ★ 错误反馈（★ 负结果，原样报）

| 观测 | 读数 |
|---|---|
| 样本数 | 24 |
| **失败类型分布** | ★ **`{'conflict': 24}` ⇒ 100% 是冲突** ⇒ **陷阱/宽度类信号根本没出现** |
| **矛盾对数中位** | **0** ⇒ ⇒ **⇒ 唯一在奖励里的项（矛盾对）恒为 0 ⇒ ⇒ 奖励实际上不区分任何行为** |
| **学出的权重** | ★ `u(修复型) = [-1.0, -1.0, -1.5, -1.5, -1.5, -1.5]` ⇒ **几乎全负、且彼此几乎无差别** |
| 结论 | ★ **权重变了但没有形成偏好** ⇒ **"权重改变行为"成立、"哪几维在起作用"不成立** |

⇒ ⇒ ★★ **⇒ 根因判定（这是本例的价值所在）**：
> **奖励里没有任何一个项能区分"踩不踩陷阱"和"分不分散"** ⇒ ⇒ 因为
> ① **陷阱命中根本没进奖励**（训练题集当时也没含带陷阱指纹的题）⇒
> ② **矛盾对数恒为 0** ⇒ **唯一的项是常数** ⇒ ⇒ **⇒ 优化器在一条平坦的地形上走 ⇒ ⇒ 权重只能是噪声。**
⇒ ⇒ ★ **⇒ 这就是"奖励与目标没对齐"的定量形态。**

## 2.4 ⇒⇒ 后续动作（★ 每条都标了是否已完成）

| # | 动作 | 状态 |
|:-:|---|---|

# 4. ★ 附：这一路踩的三个坑（**都是"看起来跑完了"型**）

## 4.1 ★ `avg_m`：把 2D 矩阵当 3D ⇒ **合并从未成功过**

```python
# merge_policies.py::avg_m（改前）
[[sum(m[i][j][k] for i in range(len(ms))) ... for k in range(len(ms[0][j]))] for j in range(len(ms[0]))]
#                                        ↑ m 是 6×6 ⇒ m[i][j] 是 float ⇒ float[k] ⇒ TypeError
```
⇒ ⇒ ★★ **而 `auto_validate.py` 的 `sh()` 把错误吞掉、继续往下跑** ⇒ ⇒ **⇒ 验证带着一个【不存在的 merged 策略】开跑 ⇒ ⇒ ⇒ 差点交出一张 merged 那列是空的表。**
⇒ ⇒ **修法**（`merge_policies.py`）：改 2D 逐元素平均 + 并集补齐 + **把 `m_shape` / `m_pad_cells` / `per_source_samples` 写进 `meta`** ⇒ ⇒ **⇒ 修后：5 进程 / 88 样本 / m_shape 6×6 / pad_cells 0。**

## 4.2 ★ `pgrep -f` 匹配到轮询命令自身 ⇒ **等待条件永远不成立**

```bash
# 改前：sh("pgrep -c -f 'train_policy_w.py.*--out runs/pl_'")
#  ⇒ 承载它的那个 bash 的命令行里就含这串 ⇒ pgrep 命中自己 ⇒ 永远等不到 0
# 改后：sh("pgrep -c -f '^python3 .*train_policy_w.py.*--out runs/pl_'")
```
⇒ ⇒ ★ **同族第三例**（今天另两例：`pkill -f` 匹配自己；`pgrep -c -f train_policy_w` 把 watcher 自己也数进去）⇒ ⇒ **通则：★ 任何"等某类进程归零"的自动化，必须按【输出路径/参数】限定，且不能只按进程名 grep。**

## 4.3 ★ `--tasks 13` 取**前 13 题** ⇒ 与预注册的"排除 A02/A05"正好相反

⇒ ⇒ ★ **教训**：★ **按数量截取题集 ≠ 按名单排除** ⇒ ⇒ 凡预注册写了"排除哪几题"，实现**必须按名单排除**。
⇒ ⇒ **修法**：`train_policy_w.py` 加 `--exclude A02,A05`（**默认空 ⇒ 行为逐字节不变**）⇒ ⇒ 留出重训用的正是它。
