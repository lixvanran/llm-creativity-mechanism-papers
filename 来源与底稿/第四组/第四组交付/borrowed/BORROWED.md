## 二、借鉴结论逐条裁决

### ✅ 成立并采纳

**① 闭合式枚举 + 干扰项 + 判别力自检（来自 multi-mind v0.8 / 三组核验器 v4）**

multi-mind 的外部判据做法：`app/eval/closed_enum.py`（闭合枚举核验器）、
`app/exp/closed_enum_selftest.py`（**判别力自检：阳性 9/9、阴性 6/6，含同义改写组**）、
`app/exp/build_user_oracle.py`（外部判据文件 = **25 probe + 8 干扰项**）。

- **干扰项（distractor）**：判据里放**应当被无视的条目**。防止模型无脑复述全部条目来刷分。
  ⇒ 第四组 CKF 判据**必须**配干扰项。
- **判别力自检**：每个判据先证明自己能抓到已知正例、放过已知负例。
  ⇒ 第四组 D-1/D-2/D-3 **每个都要配一份自检**（这是三组铁律"检查器必须先证明自己能抓到东西"的具体实现）。

**② 体裁漂移 / 对象漂移的机制描述（来自 multi-mind v0.8 §4）**

> 「工作流的『生成 + 对抗 + 递进约束』结构，会强迫模型产出一个比原始输入更『高级』的叙事 ——
> 于是它把用户的问题降格成了一个待分析的对象。」

根因在 **N2 的 schema**（强制每个候选给出「综合价值 = 收益 − 技术代价 − 合规代价 − 不可逆代价 − 声誉代价」），
不是 N3。这类 refinement 型链路「适合决策题，**对分析/创作/指导题是灾难**」。

⇒ 直接改写第四组的 C1 设计（见 §三）。

**③ 模块级消融的必要性（来自 multi-mind v0.8 §七「未知」）**

> 「工作流是否有某个特定模块单独有正贡献（**本轮是整体消融，没拆 N1/N2/N3/N4**）」

⇒ 第四组**从一开始**就要做模块级消融，不做整体消融。

**④ 判据泄漏的自我披露（来自 multi-mind v0.8 §六「未知」）**

> 「判据的 `blind=false`（措辞写在看过输出之后）」

⇒ 第四组判据**必须盲写**：先写死判据再跑第一批数据。

### ⚠️ 借鉴失败，必须降级

**⑤ ERR-DIR「零判官」路径 —— 推翻**

第四组原裁决写：「ERR-DIR 有零判官实现路径（基于三组 `ops.py` 的 verdict 枚举是规则化闭合枚举）」。

**事实核对**：`ops.py` 的 `Node.verdict` 确实是 4 值闭合枚举（`支持 / 矛盾 / 未提及 / 非主张`）✔，
但**填充 verdict 的是 LLM**——`verify_v4_borrowed.py:97` 的 `llm.chat(CHECK4...)`，
且四分类判定完全依赖提示词里的自然语言规则 ✘。

⇒ 「闭合枚举」只保证**输出空间小、解析失败可显式检出**（`verify.py` 用 `"解析失败"` 显式标记 + 3 次重试，
这本身是好设计，值得借），**不等于零判官**。
判官与被测同为 MiniMax-M3 ⇒ 撞第四组硬规则「判据与指标同源模型 ⇒ 判据无效」。

⇒ **ERR-DIR 从主判据降级为诊断项**。主判据保持 D-1/D-2/D-3（结构量，规则化 / 字面可数）。

**⑥ 外部判据文件 `user_oracle.json` —— 本机不存在**

multi-mind v0.8 引用 `/workspace/oracle/user_oracle.json`（25 probe + 8 干扰项），
但本机 `find` **无此文件**，`oracle/` 目录为空 ⇒ 与"multi-mind v0.6–v0.8 代码已丢"一致。

⇒ 只能借**方法**（闭合枚举 + 干扰项 + 自检），不能借**数据**。第四组须自建判据。

## 三、借用结论如何改写第四组设计

| multi-mind 的教训 | 第四组原本的设计 | 改写后 |
|---|---|---|
| refinement 型多步链路在创作类题目上负增益 | C1 = 多步（计划→正文→追问） | C1 保留多步，但**必须设计成 generation 型**（展开）而非 refinement 型（收敛） |
| schema 会诱发体裁漂移（N2 评分表 → 决策文档） | f(state) 输出「取舍约束」 | f(state) 输出**叙述性自然语言的取舍约束**，**禁止**评分表/对比表/字段化 schema |
| 「对象漂移」：用户本人 → 这组数据 | 未考虑 | C1 加**对象守恒门**：产出必须仍以题面主体为对象 |
| 整体消融看不出哪个模块吃掉内容 | 整体对比 C1 vs C0 | C1 内部**分步记录**，可做模块级消融（哪一步贡献、哪一步吃掉内容） |
| 缺等成本对照（1:6~7 调用比未做等成本对比） | 有 S 臂（等强度中性） | S 臂**必须等调用数**（C1 是 3 步 ⇒ S 也是 3 步），否则增益无法归因 |
| 判据 blind=false | 判据已定稿 | 判据**盲写**：先定稿再跑第一批；改动必须留痕 |

**新的强先验（必须写进第四组结论）**：
multi-mind 在 4 道题上测得直调 16 条 / 旧工作流 3 条 / 体裁自适应 8 条（可核验事实条目命中数），
即**多步 refinement 工作流在创作类题目上大概率负增益**。

⇒ 第四组的问题因此更锐利，不再是「状态机能否让内容更好」，而是：

> **状态机能否在多步管线里「保住」内容层——而不像通用工作流那样把体裁换掉？**
> 负增益是一个合法结局，必须能如实报出。
