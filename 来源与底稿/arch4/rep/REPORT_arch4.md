## 1. v4 做了什么（与 v3 的区别）

| | v3（层 2：设计手段） | v4（层 4：状态驱动） |
|---|---|---|
| 状态怎么进生成 | 状态 → **prompt 文本** → 一次生成 | 状态 → **K=3 个完整候选** → 打分 → 选 1 |
| 状态与层 2 的同构性 | 高（状态只是提示词） | 低（状态进入**选择层**） |
| 取舍代价的对手方 | 无 | ★ **被放弃的两个候选及其实际行为** |
| 主读数 | 几何相似度 + 判官 | ★ **全部零判官**（候选行为由代码从正文逐字抽取） |

v4 的关键设计约束（写在 `workflow_arch4.py` 的注释与自检里）：

1. **候选必须是完整可交付文本**。若候选只是提纲、后面再写一次正文，状态就又退回 prompt 层。
2. **打分不能直接按 priority 选**。那会恒真。⇒ 打分对象是**从候选正文抽取的实际行为**。
3. **两个打分器评估同一批候选**（`WF-v4` 与 `WF-v4-blind` 内部都这样做）⇒ 差值**只来自打分器**，不是两次独立采样。

### 1.1 行为抽取：否定语境识别（自检抓到的真实缺陷）

第一版 `extract_entities` 是纯逐字包含，自检立刻暴露问题：
候选写"这篇写甲**不写丙**"时，"丙"逐字出现 ⇒ 被算成"写了丙"。

⇒ **纯逐字包含会把"提到了但放弃了"当成命中，取舍语义根本测不出来。**
⇒ 修法：实体**前 14 字窗口**内出现否定标记（不写/放弃/不再展开/避开/略过/…）⇒ 该处计为**回避**；同一实体若既有肯定出现又有否定出现，以肯定为准。

### 1.2 恒真风险：v4 第一版被自查拦截并作废

第一版正式实验启动约 5 分钟后被**主动终止**（不是跑完再看）：

> v4 第一版候选提示**告知候选"缺口涉及的具体词"** ⇒ 候选"照做就能命中" ⇒ 状态化打分的 align 接近恒真 ⇒ **H3 失去意义**。

这是"判据可能循环，必须在跑前审"那条纪律的又一次命中（通用检查题：*这个读数能不能是恒真的？* —— 答案能 ⇒ 停）。
已落盘的 7 条**不进入任何结论**，被新一轮整批覆盖。

⇒ 修订后加 **`WF-v4-blind` 臂**：状态照常构建（观测 + 决策），但**候选提示里不含任何缺口内容/实体**，只给"有 N 个还没想清楚的地方，具体是什么由你自己判断"。
⇒ 该臂里，状态化打分**唯一的信息来源是事后从正文抽行为** ⇒ **彻底非恒真**。
（自检 25/25 含一条防回归：`blind` 提示里不得出现任何状态实体/缺口文字。）

## 4. 判决与它到底说明了什么

### 4.1 三条结论

1. **状态塑造候选是有效的。**
   `H1`（候选符合状态率）从 blind 的 **0.0741** 升到给缺口的 **0.6667**，**9 倍**。
   ⇒ 状态确实能把候选推向某个方向，v3 失败不是因为"状态没用"。

2. **状态化打分选择是无效的。**
   干净臂（blind）里，状态化打分与通用打分 **9/9 完全打平**，align 均为 0.3148。
   ⇒ 不是"方向不对"，是**零区分**。

3. ⇒ **瓶颈定位在"选择器读不出状态"，不在"状态进不了产出"。**

### 4.2 ★ 一个结构性两难（v4 真正的收获）

| 状态进候选的方式 | 后果 |
|---|---|
| **不进**（blind） | 候选不知道状态 ⇒ 产出里没有状态的指纹 ⇒ 状态化打分**无处发力**（align 0.31，两打分器同选 9/9） |
| **进**（给缺口） | 候选照做就能命中 ⇒ 状态化打分**接近恒真**（align 0.94、deep 命中 0.6574、forbidden 命中 0.5）⇒ 该臂的差值不能作证据 |

⇒ **"状态化选择"要么无效、要么恒真。** 这不是实现没调好，是**当前条件下两条路都堵死**。

### 4.3 为什么选择器读不出状态：一个可操作的诊断

状态化打分建立在"**事后猜**候选有没有写到那些实体"上。而模型**没有把状态以可抽取的形式留在产出里**：
- 取舍声明率只有 22% / 11%（`A` 臂 0%）；
- 候选即使声明了取舍，**回避的对象也常常不是状态指定的那些实体**（§3.4 里的 `R_takeoff-orig` 恒 0 就是这个现象的直接证据）。

⇒ ⇒ **要让状态化打分有意义，候选必须在可观测层面显式表达状态**（例如"我这一轮只写 A，B 就不展开了"），使打分建立在**结构化绑定**上，而不是事后猜实体命中。
⚠️ 这与第四组 v3 已确立的结论一致：**绑定必须结构化**。

## 5. 与第四组四层结构的关系

| 层 | 状态怎么起作用 | v4 之后的判断 |
|---|---|---|
| 层 2（设计手段） | 状态 → prompt 文本 | v3 失败：与层 2 同构 |
| **层 4（状态驱动）** | 状态 → 候选集合 → 选择 | ★ **v4 失败，但失败位置明确**：状态塑造有效，选择器读取无效 |
| 层 3（训练/自迭代） | 跨轮累积 | 未测 |
| **层 1（注意力机制）** | 机制性解释 | ★ **v4 的失败把问题推回层 1**：若"状态"只能以 prompt 文本或事后打分的形式进入生成，<br>那么"状态驱动"在**机制上**就还没有真正发生 ⇒ 需要在**生成过程内部**（而非外部提示/外部选择）找到状态的载体 |

⇒ **这是 v4 对第四组最实质的贡献**：它没有证明状态驱动成立，但**排除了两条最容易想到的错路**（把状态写进 prompt、把状态当打分依据），并把问题**收敛**到"状态必须在生成过程内部起作用"。

## 6. 局限（必须一起读）

1. **样本量小**：每臂每题 3 重复、3 题，共 27 条。⇒ 只支持方向性陈述，**不支持显著性主张**（Fisher p = 0.47 / 1.0）。
2. **分析单元 = 题**，但题只有 3 道 ⇒ 题间方差无法估计。
3. **取舍声明是措辞级存在性判断** ⇒ 只回答"是否出现这类措辞"，不回答"是否真的做了取舍"；且该读数是**事后追加**（`PREREG_v4.md` 补充 4，已标注），**探索性**。
4. **`H4` 违禁率样本不足**（n=2）⇒ 无法结论。
5. **只测了 G01/T07/T10 三题**，未跑禁用题（自行车大组赛、高考志愿湖北 620 分、高中爱国诗歌朗诵）。
6. **单模型**（MiniMax-M3），未跨厂商复现（OpenRouter 额度耗尽，见 §7）。
7. **`align` 这个读数本身依赖"实体"抽取** ⇒ 实体词表来自 gap 抽取，存在措辞敏感性；§3.4 的恒 0 读数已经暴露了这类脆弱性。

## 7. 下一步（按可行性排序）

1. **让状态在产出里留下结构化指纹**（解 §4.2 的两难）：
   候选必须**显式声明**"这一轮写透了 A、放弃了 B"（一句可抽取的短句），状态化打分改为**读这个声明 + 核验兑现**（声明了 A 且正文真的写到 A ⇒ 算兑现；声明放弃 B 但正文写了 B ⇒ 算违禁）。
   ⇒ 抓手现成的结构化字段，**不靠措辞相似度**（第四组已确立的纪律）。
2. **补 D0 纯重跑地板**（同候选、同打分器重选）⇒ 给出"选择差距"的地板值，判"可分辨"而非"无效应"。
3. **扩题**：3 题 → 8 题（题数靠功效公式买，题内相关 r 未测过前不预设）。
4. **跨厂商复现**：等 OpenRouter key 额度恢复，用 `grok-4.20` / `grok-4.3` 跑同一批题，检验结论是否单一模型族特性。
5. **层 1 接口**：把 §4.3 的"状态指纹"需求，转写成 transformer 注意力层面的可检验问题（当前状态只能以外部提示/外部选择进入 ⇒ 机制上未发生）。
