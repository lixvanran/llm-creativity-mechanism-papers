## §0 一句话

**v3 把状态送进了"上下文层"（状态改写 prompt），所以它与"写一条好提示词"机制同构。**
**v4 把状态送进"选择层"：状态参与在 K 个候选之间的选择。**
这是第四组研究四层结构里的**第 4 层（Agent 的状态驱动）**的最小可实现形态，也是第四组论证 §1.2b 点名的 **T1-b「取舍代价」** 的正确实现——因为"代价"必须有一个明确对手方：**被放弃的候选**。

---

## §1 为什么 v3 不算"层 4"

v3 的链路：`状态 → prompt 文本 → 生成`。
在无状态自回归 LLM 上，**"状态改了 prompt"与"写一条好提示词"在机制上没有区别**，只有 token 来源不同
（第四组论证 §3.1 / 红队 A1，已认下）。

⇒ 证据上，v3 的 `WF-a3 vs S-self`（等预算 + 取舍意识 + 无状态）在几何读数上是全部臂对中**最小**的一对（0.0591），
在判官读数上也未分离 ⇒ **状态机相对"一次性自我说明"没有可测增量**。

⇒ **v4 必须让状态改变"当下选哪个动作"**，而不只是"下一轮 prompt 怎么拼"。

## §2 前人实现的复用（不造轮子）

| 需要的能力 | 现成形态 | 本方案怎么用 |
|---|---|---|
| 候选生成 + 选择 | **Best-of-N**（生成 N 个完整候选 + verifier 打分选最优） | ★ 直接复用：K=3 个**完整草稿**候选 |
| 候选打分 | **ToT 的 value function**（同一个模型换提示词打分） | 复用"同模型不同提示词"形态，但打分维度是**与状态的一致性**，不是正确性 |
| 候选失败模式 | Best-of-N 的"代理奖励过优化"（真实奖励随 N 先升后降） | ⇒ 我们的 value 必须是**可精确核验**的（候选带结构化承诺）⇒ 不会过优化 |
| 投票的局限 | "投票只能降方差，对偏差无效" | ⇒ **不用投票**，用状态化打分 |
| 现成的评测指标名 | **"候选集合成功率"**、**"选择差距"**（候选集成功率 − 最终选中率） | ★ 直接用作 v4 的主读数，**零判官可算** |

⚠️ 另有一条来自前人经验的硬约束，直接决定了本设计：
> **"若节点只是'一段看起来合理的话'，验证往往很难落到实处。"**
⇒ ⇒ **候选必须携带结构化的、可被代码核验的"承诺"**（写什么 / 不写什么），
否则状态化打分会退化为"看起来像不像"，不可核验。

## §3 v4 机制（最小可行版）

```
                       状态 S（立场 + 取舍 + 必含/禁含 + keeps）
                              │
        ┌─────────────────────┼─────────────────────┐
        ▼                     ▼                     ▼
     候选 1                候选 2                候选 3        ← 同一状态，各生成一份完整草稿
   （各带一份结构化承诺：我要写透的实体 / 我明确不写的实体）
        │                     │                     │
        └──────────┬──────────┴──────────┬──────────┘
                   ▼                     ▼
            状态化打分（代码，零判官）   通用打分（代码，不看状态）  ← ★ 唯一差别
                   │                     │
                   ▼                     ▼
              选出 1 篇               选出 1 篇
              （WF-v4）              （WF-v4-nofilter）
                   │                     │
                   └──────────┬──────────┘
                              ▼
                    代价核验：谁被选、谁被放弃、放弃了什么
```

**为什么候选是"完整草稿"而不是提纲**：若候选只是提纲，后面还要再写一次正文，
状态就又退回"只影响 prompt"⇒ **层 4 不成立**。⇒ 候选必须是**可直接交付的文本**。

**为什么打分在代码里而不是判官**：为了**零判官可核验**（判官额度受限），
且避免 Best-of-N 的"代理奖励过优化"（我们的信号无法被欺骗，因为承诺逐字可查）。

## §4 臂（v4 批次）

| 臂 | 机制 | 生成调用数 | 状态是否参与选择 |
|---|---|---|---|
| **A** | 单次直答 | 1 | — |
| **S-self** | 等预算自我说明（无状态） | 3 | 否 |
| **WF-v4** | 状态生成 K=3 候选 → **状态化打分** → 选 1 | 3 + 决策步 | **是** |
| **WF-v4-nofilter** | 状态生成 K=3 候选 → **通用打分**（不看状态）→ 选 1 | 3 + 决策步 | 否（但有状态） |

⚠️ **`WF-v4-nofilter` 是本设计的关键对照**：它与 `WF-v4` **只差"用状态打分还是用通用打分"**，
其余完全相同（同样的状态、同样的候选、同样的生成）。
⇒ 两者之差 = **状态是否真的驱动了选择**。
⇒ ⚠️ 必须**同批**、**同候选**（同一批候选同时被两个打分器评估）⇒ **不是两次独立生成**。

## §5 读数（全部零判官）

### 5.1 候选层的可核验量

| 读数 | 定义 | 含义 |
|---|---|---|
| **候选集合成功率** | K 个候选中，**承诺与状态一致**（写透的实体 ⊆ 状态允许的"深入展开"实体，且不写的实体 ⊆ 状态允许的"放弃"实体）的候选数 / K | 候选生成是否有效 |
| **承诺兑现率** | 被选候选最终文本中，实际出现了它承诺要写的实体的比例 | 承诺是不是空话 |
| **违禁率** | 被选候选文本中，出现了状态"放弃"实体的比例 | 状态约束是否被兑现 |

### 5.2 ★ 选择层（主读数）

| 读数 | 定义 |
|---|---|
| **状态化打分命中率** | `WF-v4` 选中的候选，其承诺与状态一致的比例 |
| **通用打分命中率** | `WF-v4-nofilter` 在**同一批候选**上选中的候选，其承诺与状态一致的比例 |
| **★ 选择差距（state-driven gain）** | **状态化打分命中率 − 通用打分命中率** |
| **★ 选择差距（候选集口径）** | 候选集合成功率 − 被选中候选的命中率（即"好候选存在但没被选中"的比例） |

⇒ **H4（驱动力通路的直接检验）**：
若 **选择差距（state-driven gain）> 0 且方向在多题上一致**，
⇒ **状态确实驱动了选择** ⇒ 层 4 成立。
若 **选择差距 ≈ 0**（含负值），
⇒ **状态没有驱动选择** ⇒ 层 4 在当前实现下不成立，瓶颈在"状态与候选承诺之间的可对齐性"。

⚠️ **这个读数不循环**：候选由模型生成（承诺是模型的，不是代码强制的），
选择由代码按规则做出，**命中与否是事实**。

### 5.3 与 v3 的关系

v3 的 D2'（换决策看产出变不变）测的是"**状态改 prompt ⇒ 产出变**"；
v4 的选择差距测的是"**状态参与选择 ⇒ 选出的东西更符合状态**"。
⇒ **两者是不同的通路**，v4 不推翻 v3，v3 也不蕴含 v4。

## §6 判据（预注册，硬闸）

| 编号 | 判据 | 阈值 | 不通过时怎么写 |
|---|---|---|---|
| **H1** | 候选集合成功率 | 逐例 ≥ 2/3 | 写"候选生成无效，机制没跑起来" |
| **H2** | 承诺兑现率（被选候选） | ≥ 0.5 | 写"承诺是空话，候选不可核验" |
| **H3** | **状态化打分命中率 > 通用打分命中率** | 逐例 ≥ 2/3，且均值差 ≥ +0.15 | **不通过 ⇒ 写"状态未驱动选择"（这是负结果，不是失败）** |
| **H4** | 违禁率（被选候选含"放弃"实体） | ≤ 0.2 | 写"状态约束未被兑现" |
| **H5** | 分离的定义 | 逐例更低比例 ≥ 2/3 **且** 均值比 ≤ 0.70（沿用 v3） | 否则写"不可分辨"（不写"无效应"） |
| **H6** | 地板 | 必报 D0（纯重跑）与 D3（无关刺激） | 缺地板 ⇒ 读数不得用于结论 |

⚠️ **H3 是预注册里唯一"预期会失败"的判据**——我们**预注册它会失败**（基于 v3 的读数）。
若它通过，**必须**先检查：候选是否都相同（生成退化）？打分是否真的不看状态（实现 bug）？
⇒ **通过 H3 时必须附三项排除检查**，否则不得写入结论。

## §7 自我限制（7 条）

1. ⚠️ **K=3 是最小值**，统计效力有限；**分析单元 = 题**，绝不把"同 prompt 跑两次"当配对。
2. ⚠️ **候选生成有随机性**（MiniMax `temperature=0` 仍非确定性）⇒ 候选本身不可逐字复现。
3. ⚠️ **承诺由模型生成**，模型可能给出空洞承诺 ⇒ 必须报 **H2 承诺兑现率**，兑现率低则整个读数不可信。
4. ⚠️ **"通用打分"的定义必须公开且不含状态**（本方案：只按承诺的字数/实体数打分）⇒ 否则 H3 会被操纵。
5. ⚠️ **同源判官不可用**（本轮全零判官）⇒ 一切读数只依赖**结构化承诺的字面核验**。
6. ⚠️ **候选草稿比单次产出短**（为了控成本）⇒ 与 A 臂的产出长度**不可直接比**。
7. ⚠️ **T1-b 的"代价"只在候选层面可见**（放弃了哪两稿），**不能**推出"放弃了更优的候选"——
   "更优"需要一个质量判据，而本轮没有判官 ⇒ 只能写"放弃了另外两个候选"。

## §9 与第四组论证的对应

| 论证条款 | v4 如何对应 |
|---|---|
